# 字幕规范化、自定义纠错与练习文本净化需求规格（PRD）

> 状态：Planned（暂缓实现，纳入 R3 后续迭代，并与「自定义修改/纠正字幕」协同设计）
> 日期：2026-11-12
> 关联模块：播放器主字幕、右侧文稿（`SideSentence` / `ArticleBlock`）、翻译管线、跟读与听写工坊（`PracticeDock`）

---

## 1. 背景与核心痛点

当前 DashPlayer 的外部/自动字幕主要来自 YouTube 自动字幕（ASR）、本地 Whisper / Sherpa-onnx 转录或社区 `.srt` / `.vtt` 文件。在跟读与听写工坊（`Practice Studio`）实战中，原生 ASR 字幕暴露出 4 类典型噪声问题：

1. **非人声舞台/环境标记混入学习考核**：例如 `[Music]`、`[Applause]`、`[叹气]`、`(sighs)`、`♪ ... ♪`、`>>`。当前解析器（[`parser.ts`](../src/common/utils/subtitle/parser.ts)）仅清理了 VTT `<c>`/`<v>` 与 ASS 样式控制符；若原样进入词槽解析，会把 `[sighs]` 当成目标词汇要求听写或朗读。
2. **口语填充词与自然口误重复**：例如 `uh`、`um`、`er`、`like`、结巴重复词（`I- I think`）。原封不动强制逐词听写容易引发无效挫败感。
3. **口语数字与英美拼写变体差异**：例如字幕写成 `30`、`1999`、`colors`，用户听写按语音习惯键入 `thirty`、`colours` 时被判失分或卡槽。
4. **源头 ASR 错听与缺失标点断句**：例如将 `sort of` 识别为 `right of`，或整段无逗号句号。如果只在练习模块偷偷“硬修/删除”，会导致**画面主字幕显示的词 ≠ 听写考核的词**，分裂成两套文本真相；且用户目前无法亲手改对明显错词。

**结论**：ASR 字幕清洗不应在练习模块孤立打补丁，而应与**「用户自定义修改/纠正字幕」**统筹为一套统一能力——既不篡改原始媒体与导入源文件，又能让一处纠错同步生效到观看、生词、翻译与练习。

---

## 2. 设计原则

1. **原始字幕只读保底（Non-destructive）**：导入/解析得到的原始行文本 `rawText` 永久保留，任何时候支持单句/整片一键还原。
2. **单一修订事实源（Edited Source of Truth）**：用户手动修改或 AI 规范化产出的修订文本 `editedText`，统一作用于主字幕、右侧文稿、语境查词/生词上下文、AI 翻译基准以及跟读/听写工坊。
3. **切分状态隔离沿用既有约定**：同 `dp_subtitle_timestamp_adjustment` 与 `dp_sentence_practice_record`，字幕文本修订与 `(fileHash, sentenceIndex, resegmented)` 联合绑定，避免切换「碎句语义重组 / 语义重切分」开关后错位串行。
4. **“真听力容错”与“正式学习文本”分层**：默认忠实还原原声（仅屏蔽 `[Music]` 等非语音标记、并容错数字/拼写同义），把“是否剔除口癖、是否改为正式书面句”交由用户显式切换或单句纠正。

## 3. 核心架构：双层文本模型 + 三层练习净化

```text
原始字幕行 (rawText，来自 SRT/VTT/本地 ASR)
   │
   ▼  用户手动纠错 / AI 顺句规范化（可选，持久化修订表）
展示与学习权威文本 (displayText = editedText ?? rawText)
   │   ├──▶ 主字幕 / 右侧文稿 / 播客流 / 生词上下文 / AI 翻译
   │   └──▶ 练习工坊只读规范化投影（不写库、不改画面文本）
   │         ├─ L1 非语音过滤：跳过纯音效整行；剥离 [...] / (...) / ♪ / >> 出词槽
   │         ├─ L2 等价规则容错：数字 ↔ 英文基数词 (30 ↔ thirty)、常见英美拼写
   │         └─ L3 可选开关：忽略口语填充词 (uh / um / mm) 不计入扣分分母
```

## 4. 功能拆解与交互设计

### 4.1 字幕编辑与纠错入口（全链路协同）
* **入口一 · 主字幕 / 右侧文稿行内编辑**：悬停或快捷键触发当前句编辑框（参考既有微调时间轴入口的轻量交互），保存后即时刷新 UI 与分词缓存（`struct.blocks` / lemma），并按需触发该句 AI 译文刷新。
* **入口二 · 练习工坊交卷 Diff 页“反向纠错”**：当用户在听写对比页面（`PracticeDiffSentence`）发现标红报错词实际上是原字幕 ASR 错词时，支持点击 **`修正原字幕`** 按钮：
  1. 就地弹出/切换当前句文本编辑，回填建议修正（甚至复用用户本次听写输入一键采纳）；
  2. 确认保存后写回字幕修订表；
  3. 当场基于新 `editedText` 自动重跑一次词级对齐评分（`scoreDictation` / 重算本次 `words`），让正确付出立即拿回合理分数。
* **还原机制**：编辑过的句子角标标注细微 `已修订` 提示，支持一键恢复 `rawText`。

### 4.2 AI 辅助语料规整（可选增强，按句/选区触发）
* **能力定位**：专门针对 YouTube 自动字幕或未精校口语播客，提供「整理为标准学习句」动作。
* **整理职责（严格限定边界）**：
  * 补全缺失大小写与逗号/句末标点；
  * 合并/清理无意义口吃重复（如 `I- I think uh` → `I think`）；
  * 结合前后句语境与音频/语义上下文纠正高概率同音 ASR 错词；
  * **严禁擅自改写原意为另一种表达**（避免读音和字幕完全对不上导致听力训练失真）。
* **交付方式**：生成预览对比（原 `rawText` vs 规整建议），用户确认采纳后写入 `editedText`，不静默自动批量覆盖原片文本。

### 4.3 练习工坊三层规则净化（只读投影，零 LLM 依赖）
1. **L1 · 非人声舞台标记过滤**
   * `buildPracticeUnits` 在构筑练习队列时，若整句剥离 `[...]`、`(...)`、`【...】`、`♪`、`>>` 后不含任何有效词，则自动跳过该句、不计入练习分母；
   * 句中夹杂的舞台提示（如 `Wait [sighs] a minute.`），在跟读原文中可淡灰提示 `[sighs]`，在 [`practicePromptTokens.ts`](../src/common/utils/practice/practicePromptTokens.ts) 与 [`pronunciationScoring.ts`](../src/common/utils/practice/pronunciationScoring.ts) 中自动剔除不出词槽、不扣分。
2. **L2 · 数字与英美拼写等价容错**
   * 扩展词槽匹配与词级对齐等价表：
     * 整数基数词规范化映射（如 `0~999` 阿拉伯数字与英文拼写 `30` ↔ `thirty`、`20` ↔ `twenty`、`21` ↔ `twenty-one` 等）；
     * 常用英美词形同义集（如 `color`/`colour`、`center`/`centre`、`realize`/`realise`、`ok`/`okay`）。
   * 听写词槽匹配 `isSlotWordMatch` 命中等价词时即锁绿通过；后台对齐打分同步视作 `match`（不因美英拼写习惯差异扣分）。
3. **L3 · 口语填充词宽松开关**
   * 练习台配置项（默认关闭或按视频记忆）：开启后，`uh`、`um`、`ah`、`er`、`hmm`、`mm` 等纯填充语气词从词槽必考项降级为“跳过/不扣分”。

## 5. 数据结构与兼容性约束

1. **持久化存储建议（Main DB / Repository）**：
   * 新增字幕文本修订表 `dp_subtitle_text_revision`：
     * 复合唯一键：`(file_hash, sentence_index, resegmented)`；
     * 字段：`raw_text_hash`（防外部字幕文件整体替换后陈旧修订错挂）、`edited_text`、`source`（`'user' | 'ai'`）、`updated_at`。
2. **解析链路集成点**：
   * 在 `SubtitleService` 加载并切分出字幕句列表后，统一 overlay 应用 `dp_subtitle_text_revision` 中对应修订记录（命中且 `raw_text_hash` 匹配则替换展示 `text`，同时保留原始文本字段或由前端按需拉取对比）；
   * 确保前端 `usePlayer` 内存中修改一句字幕时同步轻量重建该句的展示与练习单元缓存，不整片重载视频解码器。
3. **历史练习记录兼容**：
   * 已入库的 `dp_sentence_practice_record` 保留产生时快照成绩，不因后续修改字幕文本强行篡改陈旧记录；仅在用户在 Diff 页主动点击「修订原字幕并重评当前输入」时写入一条新记录或按新文本刷新摘要。

---

## 6. 建议里程碑拆分

* **M1 · 基础数据与无损纠错闭环（核心价值先行）**：
  * `dp_subtitle_text_revision` 数据表与 CRUD；
  * 主字幕 / 右侧文稿单句行内编辑与还原；
  * 练习工坊 L1 `[Music]/[sighs]/>>` 过滤 + L2 数字/英美拼写同义对齐 + 听写结果页「修正原字幕并重评」闭环。
* **M2 · 智能化整理与宽松控制**：
  * L3 口语填充词（`uh`/`um`）可选跳过开关；
  * AI 单句/批次语料规整助手（去口吃、补标点、ASR 纠错建议与一键采纳/还原）。
